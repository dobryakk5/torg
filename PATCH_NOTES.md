# Исправление запуска Tenderplan / Stage 2

## Что было в логе

- Stage 1 сохранил 49 карточек, одна просроченная карточка была пропущена.
- На Stage 2 было выбрано 20 кандидатов, но обработано только 10 до аварии.
- До аварии: `GO=1`, `CAUTION=8`, `NO-GO=1`.
- Зафиксировано 15 SSL-ошибок `CERTIFICATE_VERIFY_FAILED` при обращении к `zakupki.gov.ru`.
- Зафиксировано 78 предупреждений `Package not found`: загрузчик возвращал пути к DOCX, которых физически не было на диске.
- Запуск завершился на `ValueError: A string literal cannot contain NUL (0x00) characters` при записи текста в PostgreSQL.

## Что изменено

### `database.py`

- Добавлена рекурсивная очистка `\x00` из строк, словарей, списков и кортежей.
- Очистка применяется непосредственно перед `save_detail` и при сохранении результатов фильтров.
- Поэтому PostgreSQL больше не должен отклонять извлечённый текст из документов из-за NUL-символов.

### `document_processor.py`

- `normalize_text()` удаляет NUL до нормализации пробелов.
- Загрузка страниц и файлов ЕИС использует единый CA-bundle.

### `scraper.py` и `config.py`

- По умолчанию для HTTPS используется bundle из `certifi`.
- Поддержан собственный сертификат через `EIS_CA_BUNDLE=/path/to/ca.pem`.
- Для краткой диагностики можно задать `EIS_VERIFY_SSL=0`, но оставлять отключённую проверку SSL постоянно небезопасно.

### `main.py`

- Ошибка одного тендера больше не останавливает весь Stage 2.
- Пути, возвращённые загрузчиком, считаются скачанными только при `Path.is_file()`.
- Добавлены итоговые строки:

```text
ИТОГО ЭТАПА 2: кандидатов ...; успешно ...; ошибок ...; GO ...; CAUTION ...; NO-GO ...; отправлено ...
ИТОГО ПО ДОКУМЕНТАМ: заявлено загрузчиками ...; реально сохранено ...; тендеров с извлечённым текстом ...
ИТОГО ЗАПУСКА TENDERPLAN: найдено новых ...; кандидатов Stage2 ...; детально обработано ...; отправлено ...
ИТОГО В БД: всего ...; primary-кандидатов ...; детально проверено ...
```

- Накопительная статистика по БД выводится даже при критической ошибке верхнего уровня.
- Tenderplan-тендер с номером ЕИС теперь корректно считается ЕИС-тендером при решении о скачивании документов.

## Важное ограничение архива

В переданном архиве нет каталога `sources/` и файла `sources/tenderplan.py`, хотя `main.py` его импортирует. Поэтому в этом комплекте исправлена защита на стороне `main.py`, но не сама реализация скачивания Tenderplan.

В `sources/tenderplan.py` функция `download_tenderplan_documents()` должна добавлять путь в `files` только после всех проверок:

1. HTTP-ответ успешный.
2. Тело ответа непустое.
3. Файл успешно записан.
4. `path.is_file()` возвращает `True`.
5. Размер файла больше нуля.

До этого нельзя передавать путь в `collect_document_text()` и нельзя писать в лог «скачано документов N».

## Установка

Сначала сделайте резервные копии текущих файлов проекта. Затем замените пять файлов из этого архива в корне проекта:

```bash
cp main.py database.py scraper.py document_processor.py config.py /Users/pavellebedev/Desktop/proj/torg/
```

Обновите сертификаты Python:

```bash
cd /Users/pavellebedev/Desktop/proj/torg
source .venv/bin/activate
python -m pip install -U certifi
```

Проверка синтаксиса:

```bash
python -m py_compile main.py database.py scraper.py document_processor.py config.py
```

Повторный запуск:

```bash
python main.py --tenderplan-only --only-new
```

Поскольку 49 карточек уже добавлены в БД, с `--only-new` Stage 1, вероятно, не добавит их повторно, но Stage 2 должен продолжить оставшихся кандидатов из БД. Для отдельного продолжения Stage 2 можно запустить:

```bash
python main.py --stage2
```
